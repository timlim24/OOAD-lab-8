# OOAD Лабораторна 8 — дві дороги даних: batch і streaming

Платіжні вебхуки (≈3 млн подій за жовтень 2026) проходять двома шляхами:
**батчем** через Athena і Glue на AWS, і **стрімом** — локально через Redpanda
та у хмарі через Kinesis.

| Частина | Що там | Статус |
|---|---|---|
| [Частина 1](part1-architecture/README.md) | архітектура даних Uklon: три питання | ✅ |
| [Частина 2](part2-batch-athena/README.md) | Athena + Glue Crawler над S3 | ✅ виконано на AWS |
| [Частина 3](part3-streaming-local/README.md) | Redpanda + Python, 4 експерименти | ✅ виконано на брокері |
| [Частина 4](part4-cloud-streaming/README.md) | Kinesis → Firehose → S3 → Athena + SNS | ✅ виконано на AWS |

**Усі числа в репозиторії — заміряні, не передбачені.** Батч порахований
спершу локально через DuckDB, потім перевірений запитами в Athena (збіглося
до останньої цифри); стрімінг прогнаний і офлайн, і на справжньому брокері та
в Kinesis.

## Що зламалося при реальному запуску

Чотири дефекти виявилися лише тоді, коли код зустрівся з брокером і з
акаунтом AWS — усі виправлені, усі описані в README відповідних частин:

| | |
|---|---|
| **Один watermark на 3 партиції** | відкидав **56 %** подій як запізнілі (правильно ~1,7 %). Лікується per-partition watermark із мінімумом і утриманням на −∞ для призначеної, але ще мовчазної партиції — те саме, що робить `WatermarkStrategy` у Flink |
| **`rng.choice` для причини відмови** | давав двом копіям передоставленої події різні причини й **знищував 8 % дублікатів** (1 001 → 920) — рівно той сигнал, який лабораторна вимірює |
| **`aws s3 sync` з публічного бакета** | падає на `GetObjectTagging`, хоча дані читаються; потрібен `--copy-props none` |
| **`decimal(38,0) / 100` в Athena** | обрізає копійки: 310259259 замість 310259259.21; потрібен `decimal(38,2)` |

## Швидкий старт

```bash

aws login
cd part2-batch-athena && ./setup.sh && ./setup.sh crawler

./setup.sh you@example.com
# ... потім ОБОВʼЯЗКОВО
./teardown.sh
```

## Чому все перевірено локально

Усі числа в цих README пораховані на повному датасеті через DuckDB
(частина 2) і прогоном класу `WindowedFailureRate` із
[consumer.py](part3-streaming-local/consumer.py) напряму на файлі
(частина 3, [simulate.py](part3-streaming-local/simulate.py)). Це дає еталон,
з яким можна звірити вивід Athena й консюмера — щоб відрізнити справжню
розбіжність від власної помилки.
